## 实验设置

1. 使用 cases.json 中固定顺序的 20 道合成题。题型和参考答案只用于盲评。每题创建一份全新的记忆空间。
2. 每道题的三条用户观察按日期原序、带 S1 至 S3 来源标识，作为一个原生记忆写入批次。雪午走 Cortico v0.2.8 的 CortiSoulmate Persona、原生 Memory 与 Dream。冰山走 MemoryBase 的原生写入、读取与 Persona 记忆工具。两者的应用部署、插件组合和服务配置可以影响结果。
3. 写入后用同一中文种子与答题规则创建独立答题轮，提供该记忆的前缀（最多 6,000 字符）及只读记忆工具。题面带模拟日期，末轮提问不写入记忆。写入工具预算 12 次，答题工具预算 8 次。原生适配器的提示、工具和存储仍各自不同。
4. 每次在同一模型配置的两套记忆之间交替运行。同一配置的提供商和档位相同。Sol 使用 Codex app-server，DeepSeek 使用原生 Responses，Argon 使用 OpenCode Go 原生 Gemini。manifests.json 保存各轮的档位、输出上限、超时、并发数和公共提示。
5. 盲评分开看语义正确、完整引证、沿用旧事实、无依据改写和行动归属。初判及后续复核保存在逐题记录中。失败试次不计为答题错误，比较总体可用性时分母仍是计划的 20 次。初跑 Flash 和重跑 Flash 同时改变了档位、输出上限和超时，不能从其差值隔离档位效应。雪午 Dream 在个别题中把机器日期写进了历史记录，可能影响相对时间题。

运行步骤根据实际试次记录整理。cases.json 内的 design.ingest 是早期设计说明，其中逐条写入的描述不代表本次实际执行。此小样本借鉴 STALE 的冲突与探针分类，题目由本地合成，成绩不属于论文基准或官方排行榜。模型响应和运行故障具有随机性。 [STALE 论文](https://arxiv.org/html/2605.06527v1) · [Cortico 固定版本](https://github.com/Pal-AI-Lab/Cortico/tree/cd41f48567fac115278d29cd06924151e7043503)

## 可核对文件

- cases.json 保存原样合成题、可见历史、查询、参考答案和来源编号。
- manifests.json 保存实验所用的公共参数与题集哈希。
- trials.jsonl 每行是一个试次，包括最终可见答案、评分与复核、阶段耗时、公开模型 ID、请求档位、已记录的 token 计量、工具名或次数、规范化故障码。用量缺失保留为 null。
- grading-rubric.md 保存盲评口径。summary.json 由 verify.mjs 生成，包含每组分数和共同完成题的配对情况。
- 在目录内运行 node verify.mjs 即可校验题集哈希和 200 条试次的一致性，并重算成绩。若要重跑模型，请用自己的提供商凭据，按上面的流程和 manifests.json 配置两套记忆。复算脚本仅处理已公开的记录。

逐题日志通过允许字段清单导出，不包含本机路径、部署拓扑、凭据、私人对话、评分私有映射、原始供应商请求、工具参数与返回正文，以及任何隐藏推理内容或签名。推理 token 只作为数字计量。本包只含本次合成数据和评测导出，不重新分发 Cortico 或 STALE 的源代码、数据集，也不替其更改许可证。 [Cortico MIT 许可证](https://github.com/Pal-AI-Lab/Cortico/blob/cd41f48567fac115278d29cd06924151e7043503/LICENSE)
